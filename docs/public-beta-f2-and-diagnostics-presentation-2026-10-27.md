## F2: accepted Handoff reload

Startup currently fetches the retained `datasetUrl` on each mount. With a browser-persisted Dataset, the accepted replacement guard asks again even when the fetched content is the same. Human selected an application-local recognition model for this UX change.

After a successful explicit Handoff replacement, the app records the exact URL, serialized accepted Dataset, and successful saved Dataset snapshot in tab session storage. A later startup can resume the saved Dataset without a replacement dialog only when the fetched and validated Dataset equals the accepted snapshot and the browser-persisted Dataset equals the last successful saved snapshot. The URL fragment remains intact. Edits that successfully save update only the saved snapshot. A different URL, changed fetched content, missing/unavailable recognition, mismatched saved state, or fetch/validation failure follows the guarded path; no remote content is silently accepted. Another Dataset replacement clears recognition. Storage failure restores the existing prompt. Recognition is scoped to browser session storage and is not a claim that the URL permanently identifies content.

The shortcut resumes the locally saved Dataset and its freshly evaluated Diagnostics; it does not overwrite it with the fetched copy. Cross-tab replacement refusal and save failure do not grant recognition.
