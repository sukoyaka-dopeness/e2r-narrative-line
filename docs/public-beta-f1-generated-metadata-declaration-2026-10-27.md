## Observation, classification and cause

Human observed `extension_version_unspecified` at `/extensions/metadata` after New Dataset, save and Resume, while a separately acquired Export-and-Continue JSON declared Metadata `1.0.0`. This is a valid comparison of different representations, not evidence that storage or Validator corrupted data. Source and focused automated reproduction establish **A — NarrativeLine generation inconsistency**: `createDataset()` generated `extensions.metadata.datasetId` without a Specification declaration; `updateDatasetTitle()` preserved that omission; the guarded browser save serialized the authored Dataset as-is; startup Resume imported that saved value and correctly recomputed the warning. `exportDatasetJson()` separately used `addExportSpecificationDeclaration()` to add a complete exact declaration to a copy when all used versions were known. Thus Export could be declared while the authored and saved Dataset was not. No destructive replacement or failed save was observed in this F1 investigation.

The accepted [Generated Extension Declaration Integrity decision](../../ai-knowledge/decisions/generated-extension-declaration-integrity.md) assigns exact declarations to the application when it generates an Extension, at generation rather than only Export. [Specification](../../e2r-spec/extensions/specification-extension.md) remains optional for external and legacy Datasets, but when present its `uses` inventory must be complete and it declares itself by `specVersion`, not an entry in `uses`. [Metadata 1.0.0](../../e2r-spec/extensions/metadata-extension.md) has no payload version wrapper. The correction changes neither specification contract.

## Bounded correction and ownership

New Dataset creation now places the exact Specification `0.1.0` payload beside its generated Metadata `datasetId`, with one `uses` entry for Metadata `1.0.0`. Title edits on that Dataset retain the declaration and `datasetId`. For an explicit title edit that **newly creates or removes** a Metadata payload on an imported Dataset, NarrativeLine reconciles only that Metadata use: with no existing declaration it adds a complete declaration only if every used Extension version can be stated exactly; with an existing supported Specification payload whose `uses` inventory matches the prior payload identifiers, it appends or removes only the Metadata use. It does not silently complete a Dataset on Import or Resume, rewrite existing unknown declarations, infer unsupported versions, or change unknown payloads. A title edit on an external Dataset that already had Metadata but no declaration still preserves its existing unspecified-version warning.

When an explicit title addition creates Metadata beside unknown/unsupported Extension content whose exact version cannot be established, the application leaves the Specification absent and the legitimate warning visible. This is an intentional conservative limit, not a claim that the new Metadata is fully declared. A broader refusal or recovery UX for that edit would be a separate Human product decision. Existing malformed/conflicting declarations are not repaired by this correction.
