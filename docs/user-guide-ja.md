# NarrativeLine ユーザーガイド

NarrativeLineは、E2Rデータセットを年表として見たり編集したりするアプリケーションです。このガイドでは、画面の名前ではなく、ユーザーが行いたいことを中心に説明します。

E2Rの概要は、[E2R入門ガイド](https://github.com/sukoyaka-dopeness/e2r-spec/blob/main/docs/guides/e2r-overview-ja.md)をご覧ください。

## NarrativeLineでできること

NarrativeLineでは、次のことができます。

- データセットを年表で見る
- できごと（Event）を作成・編集する
- できごとに関連するエンティティ（Entity）を結び付ける
- 日付と、必要に応じて時刻を記録する
- 結果をE2R JSONデータセットとして保存し、ほかのE2Rアプリケーションで利用する

エンティティとは、できごとに関わる人物、組織、場所、作品、物などの対象です。たとえば「アポロ11号の月面着陸」というできごとに、宇宙飛行士やNASAを関連するエンティティとして結び付けられます。

## 年表を見る

ホームで「ベルリンの壁の例を開く」を選ぶと従来の内蔵サンプルを、
「シダー天文台の例を開く」を選ぶと時間関係を含む別の物語を確認できます。
「編集を続ける」を選ぶと編集中だったDatasetに戻ります。年表（Timeline画面）は、
できごとを選び、詳細を開くための中心画面です。

年表のツールバーは作業中も利用できます。「できごとを追加」で新しい
できごとを作成できます。ページが長いときは「↑ 上へ」「↓ 下へ」で移動
できます。「その他」には「E2R Datasetを開く」と「E2R JSONを書き出す」が
あります。前者は置き換えの安全確認を経て別のローカルファイルを開き、後者
は現在の作業画面を保ったままコピーを保存します。

## 表示順を変更する

「その他」→「表示順を編集」で編集を始めます。通常のTimelineでは、Eventの行を選択・フォーカスしても↑/↓は表示されず、ドラッグしても表示順は変わりません。編集中はEventカードの操作ボタン以外の部分を別のカードへドラッグできます。移動先のカード全体の背景が変わり、細い線でそのカードの前後どちらに挿入されるかを示します。タッチ画面では通常の縦スクロールを使えます。ドラッグするときはカードを長押ししてから動かします。

↑/↓でも表示順を変更できます。Eventの行を選択するか、キーボードのTabで行にフォーカスすると操作が表示されます。カードにフォーカスした状態からEnterまたはSpaceで選択し、Tabで移動ボタンへ進めます。「表示順について」で安全上の説明と配置状態を確認できます。終えるときは「その他」→「表示順の編集を終了」を選びます。

「表示順に配置済み」と「未配置・導出表示」は表示状態を表し、新たな日時情報ではありません。

「表示順について」では、Eventを移動しても表示順だけが変わり、日時やRelative Timeの記録は変わらないことを説明します。「表示順に配置済み」は保存された表示順に含まれる状態、「未配置・導出表示」は位置が保存されず、利用できるHistoryの日時やEvent間に記録された相対時間の前後関係から位置が決まる状態です。説明は必要なときに開けるため、Timelineカード上に常時表示されません。

保存された表示順がHistoryの順序または記録された相対時間の前後関係から分かる順序と異なる場合、対象Eventの近くに「表示順を確認」が表示されます。開くと差異の詳細を確認でき、その中の「表示順を編集」から明示的に編集へ進めます。確認しただけでは編集は始まりません。Timeline上部の短い案内から診断一覧も確認できます。この診断は情報を示すもので、記録を変更したりExportを止めたりしません。
```text
ホーム
  ↓ データセットを開く
年表
  ↓ できごとを選択／追加
できごとの詳細
  ├─ 保存 → 年表
  ├─ 関連エンティティを編集 → エンティティの詳細 → 保存／戻る → できごとの詳細
  └─ 保存して関連エンティティを追加 → 関連エンティティを追加
                                      ├─ 既存のエンティティを追加 → できごとの詳細
                                      └─ 新しいエンティティを作成 → できごとの詳細
```

## できごとを作成・編集する

年表でできごとを選び、「編集」を押します。新しいできごとを追加する操作も年表から行います。名前、説明、グレゴリオ暦の日付を入力できます。「時刻を入力（任意）」を開くと、時・分・秒を追加できます。時刻は日付が記録されている場合だけ保存され、時刻の一部を消すと、それより細かい時刻情報もあわせて消えます。「できごとを保存」を押すと年表に戻ります。

## できごとにエンティティを関連付ける

できごとの詳細で「保存して関連エンティティを追加」を押します。

- 「エンティティを追加」で既存のエンティティを関連付ける
- 「新しいエンティティを作成」で名前と任意の説明を入力する
- 「作成して関連付ける」で、新しいエンティティの作成と関連付けを行う

同じ名前のエンティティも作成できます。名前だけを理由に自動統合されることはありません。必要なつながりは自動的に作成されます。関連付けを解除してもエンティティ自体は削除されません。エンティティの削除は、エンティティの詳細画面にある独立した操作です。

## 相対時間を記録する

相対時間の機能は、できごとの詳細画面で利用できます。現在のDatasetに認識できる相対時間情報がない場合は、「その他」→「相対時間の機能を表示」を選ぶと、現在のsessionで表示できます。対応する記録済み情報があるDatasetを開いた場合は、その情報に基づいて表示されます。未対応または不完全な情報は診断として表示されますが、安全に編集できない場合に編集操作を有効にはしません。

「新しい前後関係を追加（任意）」では、できごと同士の前後関係を記録します。「量的な時間関係を追加」では、暦の単位で見た位置、または経過時間を記録できます。「次の月」のような暦上の位置は、経過日数とは異なる意味です。記録した時間関係はそれぞれ独立して保持されます。

対応する直接の時間関係と記録済みの日時から計算できる場合、未記録の日時候補が表示されます。複数の候補がある場合も、それぞれ別の時間関係を根拠として示し、候補を自動選択したり、関係を連鎖させたりしません。候補はTimeline上の記録済み日時を置き換えません。「日時を確認・編集」を選ぶと、候補が日時編集欄に入力されます。日時として記録するには通常の「できごとを保存」を行ってください。編集を破棄すれば、記録済みの日時は変わりません。候補の根拠となった時間関係も保持されます。タイムゾーンとサマータイムは評価しないため、候補を確認してから記録してください。

## 自分のデータセットを使う

ホームで「新しいDataset」を選ぶと空のデータセットから始められます。「E2R Datasetを開く」では、E2R JSONファイルを読み込めます。正しいファイルは年表として開けます。JSONの構文エラーや基本仕様の検証エラーがある場合は読み込みが中止されます。NarrativeLineが知らない拡張情報が含まれていても、警告を表示したうえで開ける場合があります。

ホームには「ベルリンの壁の例を開く」「シダー天文台の例を開く」
「サンプル情報」もあります。最初の操作では従来のベルリンの壁の
サンプルを開きます。シダー天文台は別の架空の公開観望会です。
記録済みの日時は年表に表示され、招待状と最初の星空案内には、
暦月の関係と経過2時間の関係から未記録の日時候補が示されます。
ドーム準備と望遠鏡点検は前後関係でも結ばれています。
候補を選んだだけでは日時は記録されず、日時編集欄で保存したときに
初めて記録されます。「サンプル情報」は仕様リポジトリの出典・
ライセンス記録を開き、今回の公開候補の権利上の境界も示します。
シダー天文台はHub Galleryやcross-appのcanonical sampleではありません。
公開Galleryの通常の5つのsample familyと、別枠のE2R Self-Descriptionの
役割は変わりません。

## データセットを保存・共有する

年表上部のタイトル欄に名前を入力し、「タイトルを適用」を押します。タイトルは書き出すJSONにも含まれます。

「E2R JSONをエクスポート」を押してデータセットを保存します。タイトルがあればそれをファイル名に使い、なければ `e2r-dataset.e2r.json` になります。エクスポート前にもデータセットの検証が行われます。

Headerの言語コントロールでは現在の言語を確認し、Englishと日本語を切り替え
られます。Headerの「ホーム」でホームへ戻れます。詳細画面や作成画面では、
画面下部の「戻る」で前の作業画面へ戻ります。

## 作った年表をリンクで共有する

Dataset Handoffを使うと、自分で作った年表をリンクで共有できます。公開したリンクをSNSやWebサイトに載せて、多くの人に年表を見てもらうこともできます。相手はJSONファイルを手動でダウンロードして読み込む必要がありません。NarrativeLine自体がDatasetをホスティングしたり、SNSへ自動投稿したりする機能ではないため、Datasetは別途、公開HTTPS URLから取得できる場所に置く必要があります。

リンクを開くと、NarrativeLineが起動時に公開されたDatasetを取得し、年表として開きます。

### リンクを作るときの条件

URLは次の形式です。

```text
https://example.org/narrativeline/#datasetUrl=https%3A%2F%2Fexample.org%2Fhistory.e2r.json
```

Dataset URLには、公開された絶対 `https://` URLを指定します。提供元ホストは、NarrativeLineからのブラウザーアクセスをCORSで許可する必要があります。非公開URLや認証が必要なURLは、Dataset Handoff v0の対象外です。

Handoffは起動時だけ処理されます。起動後にURL末尾の追加情報を書き換えても、Datasetは切り替わらず、新しい取得も始まりません。

Handoffリンクの形式が正しくない場合や、Datasetの取得、JSON解析、またはDataset検証に失敗した場合、NarrativeLineはHomeに留まり、失敗を表示します。別のDatasetやサンプルを暗黙に開くことはありません。「編集を続ける」「新しいDataset」「E2R Datasetを開く」「ベルリンの壁の例を開く」から、明示的に操作を選べます。

リンクからDatasetを開く場合も、ほかのDatasetを開く操作と同じ作業保護が適用されます。現在の作業が失われる可能性があるときは、置き換える前に確認が表示されます。

Handoffで開いたDatasetでは、取得元へのリンクがアドレスバーに残ります。技術上はこれを`datasetUrl`と呼びますが、Datasetの同一性ではなく、現在の未書き出しの編集内容や画面の状態を表すものでもなく、Dataset JSONにも保存されません。ローカルDataset、サンプル、または新しいDatasetに置き換えると、そのリンク情報だけが削除され、その他のURL情報は保持されます。

## 詳細情報と検証

画面下部では、左側に「戻る」、右側に保存・作成などの主操作が表示されます。削除は主操作から離れた領域にあります。

History 2形式の正確な時刻を持つできごとでは、できごとの詳細画面に「日付と
時刻をおおよその値として記録」が表示されることがあります。保存しても入力
した日付と時刻は保持され、年表にはおおよその値であることが表示されます。
範囲や中央値を作成する操作ではなく、時刻だけをおおよその意味にするものでも
ありません。公開サンプルが使用するのは限定された
`history@2.0.0 / position-circa` Stable profileで、`history@2.0.0`全体が
Stableになったことを意味しません。

読み込んだDatasetに、対応する正確な形式の実験的な `linkscape-graph` 座標がある場合、エンティティの詳細画面に「記録済み座標を編集」が表示されます。変更できるのは既存の数値 `x` と `y` だけです。ほかのSpace、未記録の値、Eventの座標は読み取り専用です。

エラーはDatasetを開くことを妨げます。読み込み情報は、読み込みを妨げない注意点を説明します。旧形式の日付は、読み込み時に現在のHistory形式へ変換されます。選択した元ファイルは変更されず、エクスポートする新しいファイルでは現在の形式が使われます。Extension仕様バージョンが宣言されていない旧Datasetも読み込みと編集を続けられます。正確な診断コードとDataset内の場所（JSON Pointer）は「診断詳細」で確認できます。

狭い画面でも年表はレスポンシブに利用できます。コンパクトな移動操作を使い、
ページをスクロールして作業内容やツールバーを確認してください。編集と書き
出しの操作も同じように利用できます。

## 将来検討していること

次の項目は、今後のNarrativeLineで検討している改善案です。現在の機能や、特定のリリースで提供されることを約束するものではありません。

- できごとの名前や説明から年表を検索する
- 日付の有無などで年表を絞り込み、見たいできごとを探しやすくする
- 現在対応している範囲を超える時刻精度を扱う
- 既存のつながりを確認・編集しやすくする
- UndoやRedoなどで編集を安全に試せるようにする

候補の一つは、日付が分からないできごとの前後関係を整理することです。正確な日付が分からなくても、「このできごとはあのできごとより前だった」「AのあとにBが起きた」ということだけ分かる場合があります。将来は、そうした前後関係を指定し、年表の並びに反映できるようにすることを検討しています。
